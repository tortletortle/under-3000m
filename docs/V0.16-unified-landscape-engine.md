# V0.16 统一景观生成引擎

## 目标与边界

把 V0.13 青晶森林、V0.14 幽光孢子洞、V0.15 远古化石谷与无名黄金城的专用生成思路整理到统一的数据契约和渲染管线中。V0.16 是独立 Canvas 研发实验，不修改正式游戏 `main/index.html`、地图、碰撞、经济或存档。

实验入口：`experiments/unified-landscape-engine-v016.html`。

## 核心架构

### SceneRecipe v1

```json
{
  "schemaVersion": 1,
  "engineVersion": "0.16.0",
  "biome": "crystal | spore | fossil | city",
  "seed": 160016,
  "viewport": { "width": 960, "height": 540 },
  "palette": "biome-id",
  "params": {
    "scale": 1.0,
    "density": 1.0,
    "rough": 0.35,
    "glow": 0.72,
    "particles": 64,
    "water": 0.65
  }
}
```

### Generator / SceneGraph 契约

每个生成器接收同一份 `SceneRecipe`，返回 `{ layers, objects, ambient, palette }`。每个 layer 具有 `id`、`depth` 和 `draw(ctx, env)`。生成算法保留各自领域特征，不强行统一成一种随机算法。

- Crystal：Bridson Poisson Disk Sampling、构图锚点、参数化多面晶体。
- Spore：Poisson 群落布局、Bézier 菌柄与菌伞、菌褶、递归菌丝分枝。
- Fossil：Catmull–Rom 脊柱、椎骨采样、法线方向二次 Bézier 肋骨、独立头骨结构。
- City：确定性 Shape Grammar、拱门列、塔楼、平台、桥梁与破损参数。

### 共用管线

1. `SceneRecipe`：规范主题、随机种子、视口与参数。
2. `generators[biome]`：产生场景图和专用几何图层。
3. `LayerComposer`：按 depth 排序，并在每次重绘前重置结构计数与光源集合。
4. `LightingPass`：合成主题光、径向辉光、矿工头灯光锥和暗角。
5. 动态通道：水面波纹、粒子和瀑布高光随时间变化；静态几何不随帧变化。
6. `SceneEvaluator`：统计结构数、图层数、RGB 5-bit 颜色采样桶和亮度标准差。

提供 `registerGenerator(id, meta, fn)` 作为后续增加景观类型的扩展入口。注册的自定义生成器必须返回相同 SceneGraph 契约。

## 确定性设计

静态图层各自从 `recipe.seed` 派生独立 RNG 子流，不能在每帧继续消费共享随机数。`LayerComposer` 每次绘制前重置图层派生的对象计数和光源列表；Canvas 上下文状态也在绘制入口归一化。这样相同 recipe 的重复绘制像素一致，而动态水面和粒子仍能随 time 改变。

| 景观 | Median | P90 |
|---|---:|---:|
| 青晶森林 | 1.5 ms | 2.5 ms |
| 幽光孢子洞 | 1.6 ms | 3.4 ms |

## 视觉差距与限制

V0.16 的主要成果是统一接口、图层排序、光照通道和确定性控制，不应把它误判为已达到 AI 概念图品质。当前程序生成结果仍比概念图简单：

- 晶体轮廓和分布仍偏规则，主次簇的构图权重不足。
- 孢子洞菌伞和菌柄已成形，但表面纹理、根系与生态细节仍少。
- 化石谷的肋骨结构明确，头骨仍较抽象，缺少骨质裂纹与沉积层融合。
- 黄金城已具备塔楼、拱门、桥梁和破损参数，但城市规模层级、建筑文法多样性和石砌细节不足。

`SceneEvaluator` 目前只提供可复现的工程启发式指标（颜色桶、亮度离散度、对象与图层数量），不是经过用户研究验证的美术质量模型，也不输出“审美分数”。

## 下一阶段建议：V0.17

优先建立可解释的视觉质量评估与场景差异性测试：构图焦点位置、主次物件面积比、明暗分布、色彩主题偏差、前中后景遮挡率、生成物件重叠率和种子间多样性。指标通过后再分别提升四类生成器的细节密度，并用 AI 概念图进行并排人工审阅；不要仅凭算法自评分数自动合并到正式游戏。
