# V0.15 远古化石谷与无名黄金城：程序化景观算法实验

## 目标与边界

本轮把 AI 概念图作为视觉目标，拆解为可复现的结构规则，再由 Canvas 算法独立绘制。两个场景使用不同生成器，不直接将概念图作为游戏背景，也不修改正式游戏地图、碰撞、生态或存档。

实验文件：[`experiments/fossil-golden-landscape-lab-v015.html`](../experiments/fossil-golden-landscape-lab-v015.html)

本实验属于研究分支 `research/v0.15-fossil-golden`，以 `research/v0.14-spore-grotto` 为基础；`main` 仍保留原有 V0.12 可玩基线。

## A. 远古化石谷：曲线骨骼生成器

### 视觉拆解

- 巨型脊柱形成从左下至右上的主视觉曲线。
- 椎骨沿脊柱方向排列，提供连续骨节节奏。
- 肋骨从脊柱节点沿局部法线方向展开，形成拱廊。
- 头骨采用独立参数化轮廓，包含眼眶、上下颌、鼻孔和牙齿。
- 化石与洞穴平台、矿工、晶体和水域形成尺度关系。

### 算法

1. 使用 Catmull–Rom 样条对控制点插值，获得平滑脊柱折线。
2. 按插值折线近似等间隔采样椎骨节点；当前采用离散采样索引步长，并非严格弧长重参数化。
3. 由相邻采样点计算切线角，法线方向生成肋骨起点与端点。
4. 使用二次 Bézier 曲线构造肋骨弧线，并以外轮廓描边、内层骨色和关节节点模拟骨骼厚度。
5. 使用独立头骨多边形与局部细节绘制眼眶、颌骨和牙齿。
6. 破损参数影响控制点扰动与部分肋骨断裂；种子哈希控制裂损位置。

### 当前参数

- 结构复杂度：控制椎骨数量与肋骨长度。
- 曲线弯曲度：控制脊柱控制点偏移及肋骨弧度。
- 破损程度：控制断裂概率与控制点扰动。
- 骨骼密度：控制椎骨采样密度。
- 环境辉光：控制晶体与环境光晕。

## B. 无名黄金城：Shape Grammar 生成器

### 视觉拆解

- 中央核心塔作为固定构图锚点。
- 西侧、东侧城区沿不同层级的平台扩展。
- 桥梁由重复拱门与柱列构成。
- 塔楼、平台、阶梯和拱廊由模块化组件组合。
- 远景使用低饱和剪影，近景使用暖金色窗灯和石砌细节。

### 文法规则

```text
CITY   -> WEST + CORE + EAST + BRIDGE
WEST   -> TERRACE + ARCHROW + TOWER
EAST   -> ARCHROW + TOWER + TERRACE
BRIDGE -> ARCHROW + PILLARROW + ARCHROW
TERRACE -> PLATFORM + PILLARROW + STAIR
ARCHROW -> ARCH + ARCH + ARCH
TOWER  -> TOWER
```

规则选择由固定种子驱动；终端符号映射到可复用的拱门、柱列、平台、阶梯和塔楼绘制器。密度与复杂度会增加拱门重复次数或塔楼模块数量；曲率参数影响层级高度与平台起伏；破损参数会在拱门石砌结构中产生确定性缺口。

## C. 统一控制与可复现性

两个生成器共享同一套 UI 参数和种子接口，但保留独立的几何实现。静态场景由种子和参数决定；动画暂停时将时间输入归零，确保重复导出像素帧一致。PNG 导出使用当前 Canvas 内容。

参考图片嵌入独立实验页，仅用于视觉对照；场景由程序生成，不将参考图绘制到游戏 Canvas。

## D. Chromium / Playwright 验证

测试使用隔离页面 `page.set_content` 加载单文件 HTML，不依赖本地文件 URL 或外网资源。

| 黄金城种子 101–808 重建一致性 | 8/8 |

| 城市密度改变场景 | 通过 |
| 城市破损度改变场景 | 通过 |
| 化石破损度改变场景 | 通过 |

| 390px 视口横向溢出 | 未发现 |
| 640×360 Canvas | 通过 |
| 20 次生成平均耗时 | 约 0.97 ms |

默认参数统计：

- 化石谷：15 个椎骨节点、15 条肋骨弧线、277 个地层/晶体细节计数。
- 黄金城：33 个文法终端单元、69 个建筑模块、777 个窗灯/石砌细节计数。
- 城市密度调至 1.45× 时，建筑模块数升至 81。

耗时为受控 Chromium 环境下的生成函数测量，不代表实际帧率，也不包含浏览器合成与显示。

## E. 当前不足

- 化石谷的骨骼仍然偏示意化；头骨、肋骨厚度、埋藏关系与地质侵蚀还需要更自然的形态。
- 黄金城虽然已有文法规则，但核心城区仍偏规整；缺少更多尺度变化、非对称布局、断桥和复杂地形约束。
- 目前主要是背景景观绘制，没有把骨骼、建筑转化为可碰撞、可探索或可破坏的游戏对象。
- 尚未在实体 Android 设备上验证长时间运行、内存和真实帧率。
- 两套生成器均未合并到正式游戏主线。

## F. 下一步

V0.16 不应简单把两个实验页面拼在一起，而应抽象统一景观接口：

1. `SceneRecipe`：主题、种子、调色板、地形锚点和参数。
2. `StructureGenerator`：晶体、菌体、骨骼、建筑等主题结构生成器。
3. `LayerComposer`：背景、中景、交互层、前景分层。
4. `LightingPass`：局部光源、辉光、遮罩与调色板约束。
5. `SceneEvaluator`：构图焦点、色彩比例、层次密度和生成成本的对照指标。

只有接口、性能与风格一致性通过验证后，才考虑接入正式游戏。
